2. 技术选型
组件	选型	理由
工具语言	Go 1.21+	单文件编译、无运行时依赖、跨平台、体积小
通信协议	WebSocket over TLS	长连接、低延迟、走 443 不显眼、协议简单
服务端	Go 或 Node.js	与工具语言一致，便于维护
本机 agent 接入	MCP 或自定义 JSON 协议	看本机 agent 的编排习惯
公网入口	花生壳（个人电脑）+ DDNS	临时使用，后续可换公司公网
3. 通信协议设计
3.1 连接建立
工具启动，读取 config.json。

工具向 server_url 发起 wss 连接，携带 Authorization: Bearer <token>。

服务端校验 token，通过则接受连接，返回 {"type":"hello","client_id":"xxx"}。

工具进入待命，等待指令。

3.2 指令格式
服务端 → 工具：

json
{
  "type": "command",
  "id": "uuid",
  "action": "exec",
  "params": {
    "cmd": "ls -la /path/to/logs"
  }
}
工具 → 服务端：

json
{
  "type": "result",
  "id": "uuid",
  "success": true,
  "data": {
    "stdout": "...",
    "stderr": "",
    "exit_code": 0
  }
}
3.3 文件传输
分块传输，每块最大 1MB，带序号和总块数：

json
{
  "type": "file_chunk",
  "id": "uuid",
  "direction": "upload",
  "filename": "app.jar",
  "chunk_index": 0,
  "total_chunks": 10,
  "data": "base64..."
}
3.4 心跳
工具每 30 秒发送 {"type":"ping"}，服务端回 {"type":"pong"}。超时 90 秒未收到 pong 则断开重连。

4.2 受控 shell
go
func handleExec(params map[string]interface{}) ActionResult {
    cmd := params["cmd"].(string)
    
    // 1. 黑名单检查
    if isBlacklisted(cmd) {
        return ActionResult{Success: false, Error: "command blacklisted"}
    }
    
    // 2. 工作目录检查
    workDir := params["work_dir"].(string)
    if !isAllowedDir(workDir, config.AllowedDirs) {
        return ActionResult{Success: false, Error: "work dir not allowed"}
    }
    
    // 3. 超时控制
    ctx, cancel := context.WithTimeout(context.Background(), config.CommandTimeout)
    defer cancel()
    
    // 4. 执行命令
    execCmd := exec.CommandContext(ctx, "cmd", "/C", cmd)
    execCmd.Dir = workDir
    var stdout, stderr bytes.Buffer
    execCmd.Stdout = &stdout
    execCmd.Stderr = &stderr
    
    err := execCmd.Run()
    
    // 5. 输出截断
    out := truncate(stdout.String(), config.MaxOutputSize)
    
    // 6. 审计日志
    auditLog(cmd, out, err)
    
    return ActionResult{...}
}

生产实现的 `OSRunner` 不持有全局执行锁，各次 `exec` 可并发运行。Windows 下覆盖
`exec.Cmd.Cancel`：context 超时时对根 PID 执行 `taskkill /T /F`，并设置
`WaitDelay` 限制继承 stdout/stderr 句柄造成的等待。这样前台启动 Redis 等常驻程序
也不会永久阻塞后续命令。通用 `kill_pid` 动作用于按 PID 补充清理非 Tomcat 进程。

8. 关键流程
8.1 部署流程
运维人员 RDP 登录客户机。

把 tomcat-ops-helper.exe、config.json、新 jar 复制到客户机。

双击运行 tomcat-ops-helper.exe。

确认连接成功（控制台输出 "connected"）。

退出 RDP。

本机 agent 下发指令：replace_jar → restart。

本机 agent 下发指令：list_logs → tail 查看启动日志。

确认无误后，RDP 登录客户机，结束 tomcat-ops-helper.exe 进程。

删除 exe 和 config（可选）。

8.2 日常运维流程
RDP 登录，启动工具，退出 RDP。

本机 agent 下发 status 查看状态。

需要看日志时下发 list_logs，找到今天的日志文件名。

下发 tail 或 exec 查看内容。

需要清理僵尸进程时下发 kill_zombie。

完成后 RDP 登录，结束进程。

9. 部署拓扑
本节描述进程在网络上的位置，以及从临时方案到长期方案的演进路径。

9.1 组件角色
- helper（客户机侧）：单一可执行程序，仅做反向 wss 客户端。**只发起出站 443/TLS 连接，不监听任何端口**，因此客户机不需要入站防火墙规则，也几乎不在 netstat 上留下可疑监听。
- server（运维侧）：wss 公网入口 + 本机 agent 的 HTTP 接口。**唯一对外开 wss 的进程**，校验 token、路由指令、留审计日志。
- agent / MCP client（运维本机）：通过 HTTP bridge（默认 `127.0.0.1:7777`）下发指令。**不需要被公网访问**。

9.2 三种形态
阶段 A：单机临时（开发 / 自测）
```
┌────────────┐         ┌────────────┐
│  helper    │ ──wss──▶│  server    │ ◀──HTTP── agent / curl
│  (同机)    │         │  (同机)    │     127.0.0.1:7777
└────────────┘         │  :8443     │
                       └────────────┘
```
server 与 helper 都在运维本机，agent 也跑在同机。证书用 `cmd/gencert` 生成的自签证书，helper 配 `insecure_skip_verify: true`。

阶段 B：花生壳 + 运维本机（小规模试点）
```
┌─────────── 客户机 ──────────┐        ┌──── 公网入口 ────┐
│  helper.exe  ───出站443───▶│        │ 花生壳 DDNS     │
└────────────────────────────┘        │ ops.example.com │
                                     └────────┬────────┘
                                              ▼
┌──────────── 运维本机 ─────────────────────────────┐
│  server.exe  ◀──wss── :8443                       │
│  agent / MCP client ─── 127.0.0.1:7777            │
└───────────────────────────────────────────────────┘
```
server 仍在运维本机，公网入口是花生壳。helper 的 `server_url` 指向花生壳域名（如 `wss://ops.example.com/ws`）。

阶段 C：公司公网（长期方案）
```
┌─────────── 客户机 ──────────┐         ┌──── 公司公网 ────┐
│  helper.exe  ───出站443───▶│────────▶│ server.exe      │
└────────────────────────────┘         │ ops.corp.com    │
                                      │   :443 / 证书    │
                                      └────────┬─────────┘
                                               ▲
                                               │  仅 127.0.0.1:7777
                                               │  (VPN / SSH 隧道)
┌──────────── 运维本机 ─────────────────────────────┐
│  agent / MCP client                               │
└───────────────────────────────────────────────────┘
```
花生壳移除，server 移到公司公网服务器。agent 仍然只连本机 HTTP bridge，不再依赖花生壳。

9.3 迁移时的变更面
从 B → C 只需修改两处：
1. helper 的 `config.json`：`server_url` 由花生壳域名换成公司域名。
2. server 的 TLS 证书替换为公司正式证书（花生壳自签 → 公司 CA 签发）。

server.exe 本身、配置结构、agent 协议**全部不变**。这也是为什么 `server_url` 必须配域名、不能配 IP——花生壳地址漂移或公司公网迁移时，存量客户机 helper 不需要重新打包。

9.4 公网迁移的硬约束
- `config.json` 里的 token 与 `server.json` 的 `tokens[]` 必须保持一致，迁移后第一件事就是确认这点。
- helper 断开后若 token 不匹配，会一直 403 刷屏"reconnecting"，但不会污染数据；只需重新发布一致的 config.json 即可恢复。
- 客户机只发出站连接，**没有入站可达性需求**，因此从花生壳换到公司公网不需要修改客户防火墙 / 安全策略。

10. 风险与应对
风险	应对
花生壳地址变动导致连不上	用域名 + DDNS，不用 IP
客户安全软件拦截外连	走 443 + TLS，域名伪装成制品库
exec 误操作搞坏环境	黑名单 + 目录限制 + 超时 + 审计日志

13. 数据库工具（esb_db_operator / erp_db_operator）

13.1 模块边界

新增包 `internal/dbop`，对外只暴露：

- `Op` 接口：`Status / Query / Exec / Close`。
- `RunScript(ctx, op, script, maxRows, perStmtTimeout, totalTimeout) RunScriptResult`。
- `FakeOp`（测试用）。

生产实现 `SQLOp` 包一个 `*sql.DB`，外加三个 DSN 构造器
（mysql / sqlserver / oracle），所有驱动用空导入注册到 `database/sql`。

`internal/actions` 增加 `dbops map[string]dbop.Op` 字段 +
`WithDB(name, op)` 构造器；`Tools()` 把 `dbOpToolDefs` 里对应的条目
按 `r.dbops` 是否存在动态加入；`Dispatch` 把 `esb_db_operator` /
`erp_db_operator` 都路由到同一个 `dbOperator` 方法，按 tool name 找 Op。

server 完全不动 —— 工具全在 helper 注册。

13.2 连接生命周期

```
helper 启动
   │
   ▼
config.json 解析（ESB / ERP 可选；缺则工具不出现）
   │
   ▼
对每个 block：dbop.NewSQLOp(ctx, cfg)
   │        ├─ sql.Open(driver, DSN)
   │        └─ db.PingContext(5s)
   │              ├─ OK  → 注入到 Registry.dbops，工具亮起
   │              └─ 失败 → 仅 logger.Printf("warn: ...")，Op 仍注入，
   │                       下次调用时再重试（带「一次重试」策略）
   ▼
ws client.Run(ctx) ──▶ 每个 dbop 调用：
                          ├─ Query/Exec
                          ├─ 若 err ∈ {stale-conn, EOF, reset, ...}
                          │     关 pool → NewSQLOp → 再试一次
                          └─ 仍失败 → Result{Success:false, Error:msg}
```

13.3 SQL 脚本拆分

`SplitScript(script) []string`，按 `;` 切，保留：

- `'…'` 字符串（含 `''` 转义）
- `"…"` 标识符
- `` `…` ``（MySQL 标识符）
- `-- …` 行注释
- `/* … */` 块注释
- `$$ … $$`（Postgres dollar-quoting，兼容但不专门优化）

Oracle 模式识别 `DECLARE` / `BEGIN` 匿名块，以及 `CREATE [OR REPLACE]`
`TRIGGER` / `PROCEDURE` / `FUNCTION` / `PACKAGE` / `TYPE`。块内分号不拆分；
SQL*Plus 风格的单独 `/` 行作为客户端终止符移除，不发送给 go-ora。没有 `/`
终止符时，直到输入结尾仍视为同一个 PL/SQL 块。其他驱动继续按通用分号规则拆分。

13.4 Query / Exec 分流

`RouteStatement(stmt)` 看前导 token（先剥注释）：

| 头词 | 走 |
| --- | --- |
| SELECT / SHOW / DESC / DESCRIBE / EXPLAIN / WITH / VALUES / TABLE | Query |
| `(SELECT …)` 等括号开头的查询 | Query |
| 其他（含 `BEGIN` / `COMMIT` / 任何 DDL/DML） | Exec |

不识别时会落到 Exec 而非 Query —— 因为「把 SELECT 当 Exec」只丢列数、
「把 Exec 当 SELECT」会丢受影响行数，前者影响小。

13.5 行结果编码

`*sql.Rows` 用 `sql.RawBytes` 接列，对每个驱动都通用（INT/DATE/VARCHAR/BLOB 全能），
NULL → `nil`。列类型从 `rows.ColumnTypes()[i].DatabaseTypeName()` 取，
作为 `columns[i].type` 返回（供前端类型染色）。

`max_rows` 超限 → 截断、`truncated:true`；继续扫描少量行
（直到 `4*max_rows`）以准确报告截断。`cfg.max_output_size` 不对 dbop 结果
做截断：调用方应自行把 `max_rows` 调小，否则走 MCP 的字符串长度上限。

13.7 驱动与 DSN

| 工具 | driver 名 | DSN 形态 |
| --- | --- | --- |
| ESB | `mysql` | `user:pass@tcp(host:port)/db?parseTime=true&charset=utf8mb4&timeout=10s&readTimeout=30s&writeTimeout=30s` |
| ERP `type: oracle` | `oracle` | `oracle://user:pass@host:port/service_name` |
| ERP `type: sqlserver` | `sqlserver` | `key=value;…`（用 `url.Values.Encode`） |

MySQL / Oracle 的 password 用 `mysqlDSNEscape` 转义——**只**转义 userinfo
分隔符 `@` 和 `:`，其余字节原样透传。历史上这里用过 `url.QueryEscape`，
把密码 `yc1234!` 编成 `yc1234%21`，导致 `mysql_native_password` 握手 1045
（2026-09-14 实战 A1）。go-sql-driver 的 `ParseDSN` 在最后一个 `@` 处切分、
不做百分号解码，所以除分隔符外的字符必须逐字节保留（回归测试
`TestSQLOp_DSNPreservesExclamation` / `TestSQLOp_EnsureOpenCarriesCredentials`）。
SQL Server 走 `url.Values.Encode`，不受影响。

**MySQL 8 认证插件权衡**：MySQL 8 默认账号插件是
`caching_sha2_password`，老版本 go-sql-driver 与之握手会失败（典型报错
`Authentication plugin 'caching_sha2_password' cannot be loaded` 或 1045）。
本工具自带较新驱动、两种插件都支持，但现场排障时若客户端工具连不上而
helper 能连（或反之），先查账号插件：

```sql
SELECT user, host, plugin FROM mysql.user WHERE user = 'xxx';
-- 统一切回经典插件（现场惯例）：
ALTER USER 'xxx'@'%' IDENTIFIED WITH mysql_native_password BY '…';
FLUSH PRIVILEGES;
```

DSN 参数 `parseTime=true`（DATE/DATETIME → time.Time）、`charset=utf8mb4`
（中文四字节）、`timeout=10s`（拨号）、`read/writeTimeout=30s`（单语句 IO
兜底）——查询级超时另由 `statement_timeout` / `timeout` 参数控制，不在
DSN 层做。

13.8 失败与重试

`isRetryable(err)` 的判定很粗：包含 `broken pipe` / `connection reset` /
`connection refused` / `closed pool` / `bad connection` / `EOF` /
`i/o timeout` / `no such host` 等字样，且不是 `context.Canceled` /
`DeadlineExceeded`。SQL 语法错、权限错、配额错等一律不重试。

写操作不做自动重放：网络错误可能发生在数据库已经提交、但响应尚未到达 helper
之后，此时重试会造成重复 INSERT / UPDATE / MERGE。连接池会被淘汰，错误明确报告
提交状态可能未知，由 operator 核实后决定是否再次执行。所有非查询语句通过显式
`BeginTx` / `Commit` 执行，以规避 go-ora 对 `MERGE` 等关键字不自动提交的问题。

连接池设置 2 分钟最大空闲和 5 分钟最大生命周期；健康检查失败立即关闭死亡池。
连接成功后 best-effort 查询 session 的实际 schema（Oracle `CURRENT_SCHEMA`、SQL
Server `SCHEMA_NAME()`、MySQL `DATABASE()`），随状态和 `validate_config` 返回。

13.9 测试

- 拆分器：单 / 多语句、含 `'…'` `"…"` `` `…` `` `--` `/* */` `$$…$$`、空脚本、全空白。
- 路由：SELECT/SHOW/DESC/EXPLAIN/WITH/VALUES/TABLE/(SELECT) → Query；其他 → Exec。
- 截断：rows 超过 `max_rows` → `truncated:true`。
- 重试：FakeOp 第一次返 stale-conn 错、第二次成功 → action 返回成功
  （这条需要给 `SQLOp` 注入伪 open 函数，dbop 包提供 `NewSQLOpWithOpen`）。
- 不配置：`Tools()` 不含 dbop 工具；dispatch 返回 `"not configured"`。
