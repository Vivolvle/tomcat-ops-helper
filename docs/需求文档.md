项目名称

tomcat-ops-helper —— 临时远程运维执行器



背景与痛点

运维人员需要登录客户 Windows Server 部署和运维 Tomcat 应用，当前流程存在以下问题：



必须挂 VPN + 远程桌面：VPN 连接不稳定，RDP 会话可能被其他人顶掉，操作过程中断。



重复劳动多：停服务、换 jar、重启服务、清理僵尸进程、查看日志等操作每次都要手动敲。



日志路径每天变化：Tomcat 日志按日期命名，需要先 ls 看今天叫什么，再 tail 看内容，固定的具名动作覆盖不了。



远程桌面期间干活效率低：网络延迟高，复制大文件慢，操作体验差。



核心诉求

做一个临时启动、用完即关的远程运维执行器。运维人员通过 RDP 把工具和 jar 一起丢到客户机，手动启动工具，退出 RDP，之后通过本机 agent 远程下发指令完成运维操作。做完后再 RDP 进去关掉工具。



关键约束：客户机上只允许存在这一个进程，不允许安装任何常驻服务、驱动、exe 安装包。



目标读者

Coding Agent（负责实现本工具的 AI 编程助手）



功能需求

FR-1 绿色启动

工具为单文件可执行程序，双击或命令行启动即可运行。



不需要安装，不写注册表，不注册 Windows 服务。



启动后读取同目录下的 config.json 获取配置。



启动后主动向配置中的服务端地址建立反向连接。



连接成功后进入待命状态，等待指令。



FR-2 反向连接

工具作为客户端，主动连接运维人员本机的公网入口（通过花生壳/DDNS 暴露）。



连接协议使用 WebSocket over TLS（wss），走 443 端口。



支持断线自动重连，重连间隔可配置。



连接时携带 token 进行身份认证，token 错误则拒绝连接。



FR-3 具名动作（高频固定操作）

提供以下具名动作，参数少、返回结构化结果：



动作名	功能	参数

status	返回 Tomcat 进程状态、端口监听、JVM 信息	无

tail	返回指定日志文件尾部 N 行	file, lines

kill\_zombie	查找并清理僵尸 Tomcat 进程	pid 或 pattern

kill\_pid	按 PID 终止任意进程；Windows 默认同时终止子进程树	pid, force, tree

replace\_jar	替换指定 jar 到 webapps 目录	src, dest, restart

restart	Windows procrun 服务使用 sc stop/start 并主动等待 STOPPED/RUNNING；其他情况执行 shutdown/startup 脚本	timeout

regen\_service	根据配置重新生成 service.sh	无

list\_logs	列出日志目录下所有日志文件及修改时间	dir

FR-4 受控 shell（灵活操作）

提供 exec 动作，接受一条 shell 命令，返回 stdout、stderr、exit code。



约束条件：



工作目录限定在配置的允许目录列表内（如 Tomcat 目录、日志目录、部署目录）。



命令黑名单：禁止 rm -rf /、format、shutdown、curl | bash 等危险命令。



单条命令超时时间可配置（默认 30 秒）。



单次输出上限可配置（默认 1MB），超出截断。



每条 exec 命令及结果在服务端留审计日志。



FR-5 文件传输

支持从服务端向客户机推送文件（用于传 jar）。



支持从客户机向服务端拉取文件（用于取日志）。



传输走同一 WebSocket 通道，分块传输，支持断点续传。



FR-6 配置项

config.json 包含：



server\_url：服务端 wss 地址（配域名，不配 IP）



token：认证 token



tomcat\_home：Tomcat 安装目录



jdk\_home：JDK 目录



log\_dir：日志目录



allowed\_dirs：exec 允许的工作目录列表



command\_timeout：命令超时秒数



max\_output\_size：输出上限字节数



reconnect\_interval：重连间隔秒数



FR-7 生命周期

工具启动后持续运行，直到运维人员手动关闭（Ctrl+C 或任务管理器结束进程）。



工具不自行退出，不注册自启动，不后台常驻。



关闭后不留下任何残留文件（除日志外，日志可选）。




FR-8 数据库直连（Navicat 风格）

绕过堡垒机快速查客户的数据库：每条 DB 工具在 helper 启动时建立一条常驻连接，
operator 发的 SQL 直接走这条连接跑，不再每次都拼 `-u -p`。

两个具名动作：

esb_db_operator —— ESB 数据库（恒为 MySQL 8）。配置：`config.json` 的 `esb` 块。

erp_db_operator —— ERP 数据库（oracle 或 sqlserver，由配置决定）。配置：`config.json` 的 `erp` 块，含 `type` 字段。

行为对齐 Navicat 对话框：

- 一段 SQL 脚本，按 `;` 在字符串 / 注释外切分；
- Oracle PL/SQL 块保留内部 `;`，支持 SQL*Plus 单独 `/` 行终止且执行前移除 `/`；
- 首词为 SELECT / SHOW / DESC / EXPLAIN / WITH / VALUES / TABLE → 走 query，返回 columns + rows；
- 其他 → 走 exec，返回 affected_rows；
- 多语句脚本遇错即停，把部分结果 + `first_error` 返回；
- `max_rows` 默认 1000、上限 5000，超出截断并标 `truncated:true`；
- 每条非查询语句使用显式事务并提交，避免 Oracle `MERGE` 等语句被驱动静默回滚；
- 只读查询遇到失效连接可重连后重试一次；写操作不自动重放，避免提交响应丢失时重复 DML；
- 状态返回连接实际的 `current_schema`；SQL Server 可配置 `encrypt`、`tls_min`、
  `trust_cert`、`hostname_in_cert` 以兼容老版本实例；
- 所有 SQL 全量进 `helper.log`（沿用现有 audit 通道）。

连接策略：

- helper 启动时 `sql.Open + Ping` 一次。失败仅 `logger.Printf("warn: ...")`，**不 fatal** —— 其它动作（status / tail / exec / 上传文件）仍可用；下次调用 dbop 工具时再次尝试。
- 每次 Query / Exec 内部包了「一次重试」：第一次若因 stale-conn / EOF / 网络抖动失败，关掉旧 pool 重建后再试一次。仍失败则把错误返回给操作员。
- 连接池 `SetMaxOpenConns(4)` / `SetMaxIdleConns(1)`，单 helper + 单操作员的体量。

可选性：未配置 → 工具不出现；配置错误（host / user / password 缺一）→ 启动 warn + 工具不出现。

凭据明文：`config.json` 里 password 明文，沿用现有 token 设计；加密另议。

驱动选择（纯 Go，单 exe 不带外部依赖）：

- MySQL 8：`github.com/go-sql-driver/mysql`
- SQL Server：`github.com/microsoft/go-mssqldb`
- Oracle：`github.com/sijms/go-ora/v2`



非功能需求

NFR-1 隐蔽性

进程名命名为 tomcat-ops-helper 或类似运维工具名称。



配置中的服务端地址使用看起来像制品库或运维平台的域名。



不产生明显的异常行为（如高频外连、大量文件扫描）。



NFR-2 安全性

通信全程 TLS 加密。



token 使用长随机串，不使用弱密码。



exec 动作有黑名单和目录限制，防止误操作。



服务端保留所有操作审计日志。



NFR-3 兼容性

支持 Windows Server 2012 R2 及以上。



支持 JDK 8 和 JDK 17 两种环境的 Tomcat。



不依赖客户机上的 Python、Node.js 等运行时。



NFR-4 可维护性

单文件编译产物，便于分发。



配置文件与可执行文件同目录，便于替换。



日志输出到同目录 helper.log，便于排查。



明确不做的事

不做 LLM 集成。



不做常驻服务。



不做自启动、不做计划任务。



不做多客户机管理（一次只服务一台客户机）。



不做 Web UI（本机 agent 通过 MCP 或自定义协议调用）。



交付物

单文件可执行程序（Windows amd64）。



示例 config.json。



服务端（本机运行）的 WebSocket 接收程序。



本机 agent 侧的 MCP tool 定义或调用示例。
