# 实施计划

本文档将实现拆解为四个阶段，按优先级推进。每个阶段结束都应可运行、可验证。

---

## 阶段 1：P0 —— 最小可用闭环

**目标**：helper 与 server 能双向通信，跑通 exec 和 status 这条最短路径。

### 1.1 工程骨架
- `go mod init github.com/<org>/tomcat-ops-helper`
- 建立目录：`cmd/helper/`、`cmd/server/`、`internal/{protocol,config,actions,exec,wsclient,wsserver}/`

### 1.2 协议层 `internal/protocol`
- 定义消息结构：
  - `Hello { type:"hello", client_id }`
  - `Command { type:"command", id, action, params }`
  - `Result { type:"result", id, success, data, error }`
  - `Ping / Pong { type:"ping"|"pong" }`
- 统一 JSON 编解码辅助函数

### 1.3 配置 `internal/config`
- 客户机 `config.json`：`server_url`、`token`、`tomcat_home`、`jdk_home`、`log_dir`、`allowed_dirs`、`command_timeout`、`max_output_size`、`reconnect_interval`
- 服务端 `server.json`：`listen`、`tls_cert`、`tls_key`、`tokens`、`audit_log`
- 启动时校验必填项，缺失或格式错误直接退出

### 1.4 服务端 `cmd/server` + `internal/wsserver`
- 监听 wss（自签证书用于本地测试）
- 校验 `Authorization: Bearer <token>`
- 维护连接表（本次只一台）
- 接收本地 agent 的调用（先以本地 HTTP/JSON 暴露，便于调试），转为 command 投递给 helper，等待 result 回填

### 1.5 客户机 `cmd/helper` + `internal/wsclient`
- 读取同目录 `config.json`
- 发起 wss 连接，握手时附 token
- 收到 hello 进入待命循环
- 收到 command 后按 action 分发，将结果封装为 Result 发回

### 1.6 具名动作 `internal/actions`
- `status`：扫 Tomcat 进程、监听端口、JVM 信息
- `list_logs`：列出 `log_dir` 下文件 + 修改时间 + 大小
- `tail`：读文件尾部 N 行
- `restart`：调 `shutdown.sh` / `startup.sh`（Windows 下为 `shutdown.bat` / `startup.bat`），带 timeout
- `replace_jar`：把 src 拷到 webapps 目标 jar，可选 restart

### 1.7 受控 shell `internal/exec`
- 黑名单正则：`rm\s+-rf\s+/`、`format`、`shutdown`、`curl\s*\|\s*bash`、`wget\s*\|\s*bash`、`del\s+/f\s+/s\s+/q\s+C:\\`、`rd\s+/s\s+/q\s+C:\\`、`net\s+user`、`net\s+localgroup` 等
- 目录白名单：执行前把 cmd 中出现的路径做前缀检查
- `context.WithTimeout` 控制超时
- 输出上限 1MB，超出截断并标注
- 每条 exec 落审计日志（命令、退出码、耗时、输出摘要）

### 1.8 单文件编译
- `build.bat`：`go build -ldflags="-H windowsgui -s -w" -o tomcat-ops-helper.exe ./cmd/helper`
- 同样脚本产出 `tomcat-ops-helper-server.exe`

### 阶段 1 验收
- 本机启动 server，自签证书监听 443
- helper 启动后控制台打印 `connected`，server 端能看到 client_id
- 通过本地 HTTP 调用触发 `status`、`exec` 各一次，结果正确返回
- exec 黑名单命中时返回 `success:false, error:"command blacklisted"`
- 错误 token 时 helper 连接被拒

## 阶段 2：P1 —— 实战化

**目标**：把工具从"能跑"变成"敢在客户机上跑"，加上稳定性、安全性、可观测性。

### 2.1 断线重连
- helper 端：连接断开后按 `reconnect_interval` 重连，指数退避封顶 60s
- 重连成功后通知 server 本端已重置上下文

### 2.2 心跳
- helper 每 30s 发 `ping`，server 回 `pong`
- server 90s 未收到任何消息则主动断开
- helper 90s 未收到 pong 则强制重连

### 2.3 文件传输 `internal/transfer`
- 协议消息：`FileChunk { id, direction:"upload"|"download", filename, chunk_index, total_chunks, data(base64) }`
- 块大小 1MB
- 上传：helper 端写文件，server 落盘到指定目录
- 下载：helper 端按 chunk_index 写入磁盘，server 按请求回发
- 断点续传：helper 端记录已收到的最大 chunk_index，重连后向 server 报 `Resume { filename, from_index }`

### 2.4 审计日志
- helper：`helper.log`（JSON Lines，字段：ts、action、params、success、duration_ms、output_bytes）
- server：`audit.log`（JSON Lines，额外含 client_id、remote_addr）

### 2.5 MCP tool 封装 `internal/mcpserver`
- 注册 tool：`tomcat_status`、`tomcat_list_logs`、`tomcat_tail`、`tomcat_exec`、`tomcat_replace_jar`、`tomcat_restart`、`tomcat_kill_zombie`、`tomcat_regen_service`、`tomcat_upload`、`tomcat_download`
- tool 调用内部走本地 HTTP → server 已有路由 → helper

### 阶段 2 验收
- 主动 `kill` helper 进程后重启，自动恢复连接
- 拔网线 10s 恢复，心跳与命令正常
- 上传 100MB jar 到 helper，能完整落地，sha256 一致
- 中途中断后重连，server 续传缺失块
- 审计日志可在 server 与 helper 端分别查到

## 阶段 3：P2 —— 完善

**目标**：补齐次要动作、体验打磨、可移植性。

### 3.1 补全具名动作
- `kill_zombie`：按 pid 或 pattern 找僵尸进程，Windows 下用 `tasklist` / `taskkill /F /PID` 配合 jstack 输出
- `regen_service`：根据 `tomcat_home`、`jdk_home` 重新生成 `service.sh`（Windows 下生成 `service.bat` 或 wrapper 配置）

### 3.2 输出截断优化
- 超长输出保留头尾各 32KB，中间省略并标注 `[... truncated N bytes ...]`
- 二进制检测：输出含 NUL 字节时转为 base64 + 标注

### 3.3 控制台友好输出
- helper 启动横幅、连接状态、最近一次指令结果摘要
- 可通过 `-quiet` 静默

### 3.4 跨平台兼容
- 路径分隔符统一用 `filepath.Join`
- `runtime.GOOS == "windows"` 分支处理 `.bat` vs `.sh`
- 兼容 Win Server 2012 R2：避免使用 Go 1.21 之后才引入的 syscall，必要时降级到 1.21 仍可用的 API

### 阶段 3 验收
- 控制台输出在无人值守时不影响审计可读性
- 在 Win Server 2012 R2 / 2019 / 2022 三种系统上均能正常启动与连接

## 阶段 4：验证与交付

**目标**：跑完测试矩阵，产出可分发的交付物。

### 4.1 测试矩阵
| 用例 | 期望 |
| --- | --- |
| 错误 token 连接 | 服务端主动关闭，helper 进入重连循环 |
| 正确 token 连接 | 收到 hello 进入待命 |
| `status` | 返回进程、端口、JVM 完整信息 |
| `exec ls` | stdout/exit_code 正确 |
| `exec rm -rf /` | 返回黑名单错误 |
| `exec` 在不允许目录 | 返回目录不允许 |
| `exec` 超长输出 | 截断并标注 |
| 主动 kill helper | 自动重连成功 |
| 拔网 10s | 自动重连成功 |
| 上传 100MB jar | 完整且 sha256 一致 |
| 上传中断后续传 | 仅传缺失块，最终一致 |
| Win Server 2012 R2 | 启动、连接、exec 均正常 |
| JDK 8 + JDK 17 双环境 | `status` 读到的 JVM 版本正确 |

### 4.2 交付物
- `tomcat-ops-helper.exe`（客户机端，单文件）
- `tomcat-ops-helper-server.exe`（运维本机服务端）
- `config.example.json`
- `server.example.json`
- `README.md`：部署流程、日常运维流程、风险与应对
- `helper.log` / `audit.log` 字段说明

### 4.3 风险复核
- 花生壳地址漂移：已使用域名 + DDNS
- 客户安全软件拦截：走 443 + TLS，进程名伪装
- exec 误操作：黑名单 + 目录限制 + 超时 + 审计已覆盖
- 断线丢指令：心跳 + 重连 + 重发已覆盖
- 大文件中断：分块 + 断点续传已覆盖

---

## 执行顺序建议

按阶段 1 → 阶段 2 → 阶段 3 → 阶段 4 顺序推进，每个阶段结束做一次 commit 与验收，再进入下一阶段。任一阶段验收失败应就地修复，不向后堆积。
